## Что получилось

```
Mac: notebook-sync (раз в 15 мин) ── PUT /notebook/{ws}/sources ──▶ API: разбивка по заголовкам → notebook_chunk
Mac: notebook-worker (всегда) ◀── long-poll /embed/work ── очередь: чанки и запросы поиска
                              ── Ollama nomic-embed-text, по одному ──▶ /embed/results → вектор в БД
Читатель ── POST /search ──▶ ключевые слова (russian tsvector) + векторы (если воркер онлайн) → RRF
        ── POST /threads ──▶ поиск 6 источников → модель (OpenAI-совместимая) → ответ со ссылками [n]
```

- **Источники.** Документ хранится один раз по `ref`, повторная заливка без изменений ничего не делает (sha256).
  Разбивка — по заголовкам Markdown, заголовок чанка — путь «Лес › Аренда». Источники, которых нет в синхронизации,
  удаляет `/sources/prune`. Лимит текста — 500 000 символов.
- **Эмбеддинги.** Сервер Ollama не вызывает. Mac-воркер забирает работу long-poll-ом с арендой, считает вектор и
  возвращает его. Векторы чужой модели и битые — отклоняются. Воркер считается онлайн 40 с после последнего запроса.
- **Поиск.** Ключевые слова — `websearch_to_tsquery('russian')` плюс английские основы. Векторы — косинус по индексу в
  памяти, вектор запроса воркер считает за 4 с. Если воркера нет или он не успел, поиск честно отвечает
  `mode: keyword`. Списки сливаются RRF.
- **Чат.** Тред — это вопросы и ответы. Ответ пишет любая OpenAI-совместимая модель (по спеке — бесплатные NVIDIA через
  OpenRouter, R-052), и только по найденным источникам, со ссылками `[1]`, `[2]`. Источники в промпте помечены как
  данные, а не инструкции. В уточняющем вопросе модель видит до 6 прошлых реплик, а источники ищутся заново по новому
  вопросу.
- **Статус ответа:**
  - `answered`;
  - `retrieval-only` — модели нет или ничего не нашлось, читатель получает источники;
  - `capped` — дневной лимит вызовов `NOTEBOOK_LLM_DAILY_MAX`, по умолчанию 500. Лимит общий на весь сервис: он
    бережёт один ключ, а не делит квоту между пространствами. `0` выключает вызовы, пустое значение — 500;
  - `rate-limited` — модель ответила 429. Короткую паузу (≤ 20 с) сервер выжидает один раз, другого провайдера не
    ищет (R-053);
  - `failed`.
- **Права.** Читать, искать и спрашивать — `workspace:read`. Заливать источники и удалять треды — `manage_settings`.
  Воркеру нужен API-ключ пространства. Тред из чужого пространства — 404.
- **Секреты.** Ключ модели — только файлом `NOTEBOOK_LLM_KEY_FILE`, читается при каждом вызове: смена ключа без
  рестарта. В ошибки не попадают ни ключ, ни URL, ни тело. Телеметрия исходящих запросов для вызова модели выключена.

## Защита (автоматическое ревью, 28.10)

Три находки ревью безопасности исправлены в `c29ab3b`:

- **Тело поиска без лимита.** Теперь `POST /search` читает не больше 8 КБ до разбора JSON, дальше 413 — как у
  источников и чата.
- **Гонка на дневном лимите.** Проверка «сколько вызовов сегодня» и сам вызов были разнесены: пачка одновременных
  вопросов проходила проверку вся. Теперь вызов занимает место до записи ответа, проверки и освобождения идут по
  одной (`chat/call-budget.ts`). Места живут в памяти процесса: блокнот работает на одном экземпляре API.
  Тест: 6 вопросов разом при лимите 2 — ровно 2 ответа и 2 вызова модели.
- **Индекс векторов ограничивал строки, а не байты.** Модель на 4096 измерений давала до 328 МБ на пространство.
  Теперь бюджет — 32 МБ на индекс (≈ 10,9 тыс. чанков по 768) и 64 МБ на весь кэш. Сверх бюджета вытесняются давно
  не использованные пространства.

Попутно найден ещё один баг: compose передаёт незаданную переменную пустой строкой, а `Number("")` — это 0. Пустой
`NOTEBOOK_LLM_DAILY_MAX` выключил бы все ответы. Теперь пустое значение означает 500.

## TB-2: PR GitHub и ссылки (04.11)

Правка карточки перестраивает её источник уже со среза 3 (`sync-card-sources.ts`, cron `*/10` и кнопка). TB-2
добавляет два вида, оба — только явным добавлением, `manage_settings`. Повторное добавление («Обновить» в строке
источника) перечитывает и заменяет текст на месте; тот же текст — `changed: false`.

- **PR** — `POST /notebook/{ws}/sources/github-pr`, `url` — ссылка на PR или ref `owner/repo#12`. Нужна проверенная
  интеграция GitHub на этот репозиторий у активного проекта пространства, открытого всем участникам (R-041: треды общие,
  токен приложения не тратится на чужие репозитории). Через `getVerifiedInstallationOctokit` (ограниченный клиент:
  16 МБ, 10 с, без повторов): `pulls.get` и первая страница `issues.listComments`. Лимиты: описание 50 000 символов,
  100 комментариев по 4 000. ref — `owner/repo#n` в нижнем регистре. Отказы: 400 `PR_INVALID_URL`,
  422 `PR_REPO_NOT_LINKED`, 404 `PR_NOT_FOUND`, 502 `GITHUB_UNAVAILABLE`, 503 `GITHUB_APP_NOT_CONFIGURED` — без 500.
- **Ссылка** — `POST /notebook/{ws}/sources/link`. Защищённый клиент импорта (`createGuardedFetch`) с двумя новыми
  флагами:
  - `httpsOnly` — https на каждом прыжке, до 3 редиректов;
  - `alwaysPublic` — адрес проверяется до запроса и при соединении (`publicDestinationFetch`), а
    `KANEO_ALLOW_PRIVATE_WEBHOOK_DESTINATIONS` для ссылок не действует: API на VPS видит туннель, Postgres и Redis.

  Ограничения: 2 МБ декодированного тела, один срок 10 с на DNS, редиректы и тело, типы `text/html`, `text/markdown`,
  `text/plain`; текст — не длиннее `SOURCE_TEXT_MAX`. У каждого отказа свой код: `LINK_NOT_HTTPS`,
  `LINK_PRIVATE_DESTINATION`, `LINK_TIMEOUT`, `LINK_TOO_LARGE`, `LINK_CONTENT_TYPE`, `LINK_PDF_UNSUPPORTED`, `LINK_EMPTY`
  и другие. Коды переведены в UI.
- **HTML → текст без turndown.** Замер на враждебной странице: 20 000 `<br>` — 1,6 с, `<pre>` с 20 000 пробелами и
  табами — 1,6 с. Рост квадратичный, 2 МБ держали бы цикл событий минуты; 5 000 вложенных `<div>` — переполнение стека.
  Поэтому `html-text.ts` — один проход по `indexOf`, без рекурсии: 2 МБ таких страниц — до 45 мс. Он оставляет
  заголовки, абзацы, списки и `<pre>`, а скрипты, стили, `nav`, `footer` и `svg` выбрасывает.
- **Нарезка.** Ленивая регулярка заголовка в `chunk-markdown.ts` тоже была квадратичной: строка `# x###…y` из 8 000 `#`
  — 69 мс, из 400 000 — минуты. Теперь закрывающие `#` отрезаются руками, линейно. Заодно «## C#» больше не
  превращается в «C». После ревью убраны ещё три дыры:
  - `\s` вместо `[ \t]` давал квадратичный откат на строке, кончающейся U+2028: 40 000 символов — 0,8 с;
  - заголовок теперь обрезается до 200 символов, путь — до 500. Иначе каждый чанк копировал заголовок
    в 250 000 символов, и тысячи разделов забивали кучу;
  - чанки вставляются пачками по 1000, потому что 55 000 строк упирались в лимит Postgres на 65 535 параметров и
    давали 500. Ссылка и PR дают не больше 2000 чанков (413 `SOURCE_TOO_MANY_CHUNKS`).
- **PR уходят вместе с доступом.** Задача планировщика раз в 10 минут удаляет PR тех репозиториев, у которых больше
  нет связи с проектом, открытым всем: проект закрыли, архивировали или сняли интеграцию (R-041, как с карточками).
  GitHub 401/403 — 422 `GITHUB_NO_ACCESS`.
- **HTML после ревью.** Поиск закрывающего тега идёт без `toLowerCase()`: «İ» превращается в два символа, и на

  новой строки. `<3` — это текст, а не тег. Сущности раскрываются до схлопывания пробелов.
