### Узкое место — водопад модулей, а не вес и не CPU

Сеть без CPU-замедления даёт 15 с, CPU ×4 без сети — 4 с. На первую карточку уходит ~240 запросов модулей:
маршрут доски грузит ленивые чанки по цепочке, каждое звено ждёт RTT. Тёплый кэш почти не помогает (14 с при 53 KB
трафика): ассеты отдаются без заголовков кэша, и браузер перепроверяет каждый модуль (`ETag` → 304) — так же в
продовом `apps/web/nginx.kaneo.conf`, где блок кэширования ассетов закомментирован.

Рекомендации (по убыванию отдачи на цену):

1. **Кэш ассетов с хэшем в имени** — `Cache-Control: public, max-age=31536000, immutable` для `/assets/`. Тёплый заход
   на 3G теряет ~240 RTT. Но сейчас `env.sh` при каждом старте контейнера переписывает переменные прямо в бандлы:
   сменить адрес API на том же образе — и клиенты с вечным кэшем держат старый. Поэтому сначала (2), потом (1).
   Правка деплой-конфига — по «да» владельца.
2. **Переменные окружения — в маленький `/env.js` без кэша**, который подключает `index.html`, вместо переписывания
   бандлов. Бандлы становятся неизменяемыми, (1) — безопасным.
3. **Сократить глубину цепочки маршрута доски** — `modulepreload` статических зависимостей маршрута или укрупнение
   чанков (`manualChunks` для доски, i18n-неймспейсов, иконок). Цель — первая карточка на 3G ≤ 5 с; проверить
   `measure-mobile.mjs`.

### Рекомендация 3 — чанки маршрута доски (TB-15, 13.11)

Разбор манифеста сборки: дело не в глубине цепочки. Vite грузит зависимости маршрута параллельно (`__vite__mapDeps`).
Время уходит на число запросов и на редактор. Доска тянула 215 чанков, 161 из них меньше 2 KB gzip: отдельные иконки
lucide, части base-ui, внутренности TanStack, мелкие хуки запросов. Ещё 199 KB gzip — редактор tiptap. Его статически
подключали модалка новой задачи и шторка карточки, хотя обе открываются по действию.

Сделано:

- Редактор описания в `create-task-modal.tsx` и содержимое шторки в `task-details-sheet.tsx` грузятся при первом
  открытии через `lazyPart` (`apps/web/src/components/ui/lazy-part.tsx`). Пока чанк идёт, на месте части — скелетон.
  Чанк пропал после выкладки — страница перезагружается один раз: та же проверка и тот же ключ `sessionStorage`, что
  у `lazyRouteComponent` маршрутов. Другой сбой — «Повторить» на месте части, а не корневой экран сбоя; второй сбой —
  перезагрузка. Ошибки рендера идут к внешней границе, как раньше.
- `apps/web/vite.config.ts`, `build.rolldownOptions.output.codeSplitting`: две группы — внутренности TanStack и мелкие
  общие модули `src/` (не больше 4000 байт, нужны ≥ 2 точкам входа). Чанки маршрутов, иконки и base-ui остаются
  раздельными.

Выбор сделан по HTTP/2: edge отдаёт h2 (`deploy/vps/tls.conf.template:31`). Замер: Chromium 1228 headless, 3G
(1,6 Мбит/с вниз, RTT 300 мс), gzip 6 как в nginx, медиана 3 прогонов. «Сеть JS доски» — две волны (entry →
маршрут доски); «вход» — холодный `/auth/sign-in` до текста страницы.

| Сборка | JS доски: файлов / KB gzip | Сеть JS доски, h2 / HTTP/1.1 | Вход: файлов / KB gzip | Вход h2, CPU ×1 / ×4 | Вход HTTP/1.1, CPU ×1 / ×4 |
|---|---|---|---|---|---|
| До | 215 / 974 | 6,63 / 12,97 с | 73 / 384 | 4,18 / 4,20 с | 6,18 / 6,19 с |
| Только ленивые части | 219 / 746 | 5,53 / 12,61 с | 75 / 382 | 4,19 / 4,22 с | 6,15 / 6,20 с |
| **+ TanStack и общие `src/` (выбрано)** | 96 / 704 | **4,70 / 7,54 с** | 21 / 404 | 4,33 / 4,67 с | 4,78 / 4,96 с |
| + иконки и base-ui | 53 / 693 | 4,44 / 5,77 с | 18 / 476 | 4,27–4,41 / 4,85–5,32 с | 4,68 / 4,80 с |

Для последней строки вход по h2 замерен двумя сериями, поэтому даны диапазоны.

Отклонено:

- **Группы иконок и base-ui.** По h2 доска быстрее на 0,26 с. Но вход тянет все иконки приложения (+72 KB gzip к
  выбранному варианту), и слабый CPU платит за это на входе 0,2–0,65 с. Ещё чанк иконок перекачивается целиком при
  любом новом значке в приложении. По HTTP/1.1 этот вариант лучше на 1,8 с, но edge отдаёт h2.
- **`entriesAware` и общая группа всего `src/`.** Первая загрузка росла до 1,3–2 MB, доска получала 95–120 чанков.
- **Ранняя подгрузка редактора (idle или наведение).** Это ~220 KB трафика на 3G для тех, кто карточку не открывает.
  Вернуться к ней, если замер на стенде покажет задержку открытия карточки.
- **Общий обработчик `vite:preloadError`.** Обе ленивые части закрывает `lazyPart`, маршруты — `lazyRouteComponent`.

Чем мерили (скрипты из scratchpad сессии, в репозиторий не входят): манифест `vp build --manifest`; CDP
`Network.emulateNetworkConditions`; статический сервер с gzip 6 (h2 — через TLS с самоподписанным сертификатом);
заглушки `KANEO_*` подставлены, как это делает `env.sh`. Без API доску целиком не открыть, поэтому для доски замерена
сетевая часть её JS. Ответы API и рендер одинаковы во всех сборках. Полный повтор `measure-mobile.mjs` со стендом и
API — после выкладки.
