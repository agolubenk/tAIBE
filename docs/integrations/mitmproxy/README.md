# mitmproxy — разбор встраивания

> **Статус (2026-11-14):** ✅ берём как локальный инструмент, без кода в продукте. Источник —
> [mitmproxy/mitmproxy](https://github.com/mitmproxy/mitmproxy). Как запускать — [`../../ops/mitmproxy-local.md`](../../ops/mitmproxy-local.md).
> Индекс и правила — [`../README.md`](../README.md).

## Что это

Перехватывающий HTTP/HTTPS-прокси: консоль (`mitmproxy`), веб-интерфейс (`mitmweb`), скрипты (`mitmdump`). Python,
лицензия MIT. Проверено 14.11.2026 через GitHub API: последний релиз `v12.3.1` от 2026-10-25, репозиторий активен (не
в архиве, последний push — 2026-11-13). Ставится как brew cask: подписанный бинарник проекта, brew сверяет sha256.

## На что ложится в tAIBE

R-075 и N-006 спеки досок: ручная проверка безопасности только на Mac владельца. Скрипт
`infra/scripts/security/mitmproxy-local.sh` ставит mitmweb перед локальным стендом досок (`boards/compose.local.yml`).
Это заменяет hetty в S24-1 ([`../hetty/README.md`](../hetty/README.md)), а не часть продукта: раньше локального прокси
не было.

## Как встроено (вариант B — адаптер без кода инструмента)

| Что | Как |
|---|---|
| Сеть | прокси и веб-интерфейс — только `127.0.0.1` (`--listen-host`, `--web-host`) |
| Доверие к CA | CA не попадает в системный keychain; Chrome доверяет ему только в своём профиле, по хэшу SPKI |
| Данные | вне git, каталог `~/.local/state/taibe-mitmproxy` с правами `700`; удаление — `remove-data` |
| Версия | cask нельзя закрепить через `brew pin`, поэтому скрипт сверяет `mitmdump --version` с `VERSION` |

## Проверка «усиливает, а не заменяет»

- Дополняет: до этого локального прокси для досок не было.
- Снаружи ничего не меняется: ни PR, ни CI, ни прод. Инструмент только на Mac, только на `127.0.0.1`.
- Лицензия MIT; код mitmproxy в репозиторий не берётся.
- Ресурсы Mac: mitmweb — один процесс Python, запускается руками на время проверки.
- Данные: перехваченный трафик остаётся на Mac, в каталоге данных; в репозиторий он не попадает.
