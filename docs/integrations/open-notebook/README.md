## Что это

Свой аналог Google NotebookLM: блокноты, источники, заметки, чат по источникам, поиск, подкасты. MIT, 42 тыс. звёзд,
релизы раз в 1–2 месяца (`v1.14.0` 21.07, `v1.15.0` 04.10, `v1.15.1` 04.11). Проверено через GitHub API 20.11.

| Часть | Что | Где в источнике |
|---|---|---|
| API | FastAPI + uvicorn, порт 5055 | `supervisord.conf` (`program:api`), `api/main.py` |
| Фоновые задачи | `surreal-commands-worker`, до 5 задач разом | `supervisord.conf` (`program:worker`) |
| UI | Next.js на Node 22, порт 8502 | `Dockerfile` (`node:22-slim`), `supervisord.conf` (`program:frontend`) |
| База | SurrealDB v2 (RocksDB), отдельный контейнер | `docker-compose.yml` |
| Извлечение | `content-core` (MIT): PDF, Office, EPUB, веб, YouTube, аудио; опции Docling (ML и OCR) и Crawl4AI (Chromium) | `pyproject.toml`, `docker-compose.yml` |
| Модели | `esperanto` + LangChain/LangGraph, 20+ провайдеров, ключи хранятся в базе зашифрованными | `pyproject.toml`, `README.md` |
| Доступ | один общий пароль `OPEN_NOTEBOOK_PASSWORD` (Bearer), по умолчанию его нет; SurrealDB по умолчанию `root:root` | `api/auth.py`, `docker-compose.yml` |
| MCP | отдельный пакет `open-notebook-mcp` (uvx) поверх REST API | [mcp-integration](https://github.com/lfnovo/open-notebook/blob/v1.15.1/docs/5-CONFIGURATION/mcp-integration.md) |

Образы (Docker Hub, 20.11): `lfnovo/open_notebook` около 580 МБ сжатого (arm64; amd64 — 592 МБ), `surrealdb/surrealdb:v2`
около 30 МБ.

## На что ложится в tAIBE

На блокнот досок (`boards/apps/api/src/notebook/`). Он уже есть и работает внутри процесса API:

| Возможность | Наш блокнот (`board-agents`, 20.11) | open-notebook | Разница |
|---|---|---|---|
| Источники | текст карточки, PR GitHub, ссылки HTML/Markdown/текст (`notebook/sources/`); PDF отклоняется (`link-fetch.ts:167`, `source-routes.ts:187`) | PDF, Office, EPUB, видео, аудио, веб | **у нас нет PDF и медиа** |
| Поиск | гибрид RRF k = 60 (`fuse-ranks.ts:1`), без воркера — ключевые слова (`search-notebook.ts:55`) | полнотекстовый или векторный, режим выбирается | у нас не хуже: слияние рангов и деградация без векторов |
| Чат | по источникам, недоверенный текст в разделителях с nonce (`chat/build-prompt.ts`, идея agno) | по источникам, со ссылками на источники и заметки | сопоставимо |
| Агенты | MCP `notebook_search` и бриф (TB-3) с бюджетом токенов ответа | REST API и отдельный MCP-пакет | у нас уже в хабе и в правилах бюджета |
| Граница продукта (R-002) | поиск в пределах пространства (`search-notebook.ts:41`) | пространств и пользователей нет, один пароль на всё | **нарушает R-002** внутри одного экземпляра |
| Подкасты | нет | есть | требования к продукту нет |
| Ресурс | в процессе API, своей базы нет | +2 контейнера, своя база | RAM не измерена |

- [x] Инвариант «снаружи ничего не меняется»: A и B не трогают PR, карточки, очередь и бот; C добавляет второй UI.

      Python-процесс. Отказ: при A ничего нового не падает; при B отказ сервиса — ссылка отклоняется, как сейчас.

## Замер (не измерено)

Скрипт — [`infra/scripts/misc/open-notebook-measure.py`](../../../infra/scripts/misc/open-notebook-measure.py). Свой
compose-проект `tb-on-f2bs`, порты только `127.0.0.1:15055` (API) и `127.0.0.1:18502` (UI), синтетический текст, без
ключей моделей, случайные пароли не печатаются. Замер: время скачивания и старта, RAM и CPU каждого контейнера в простое
60 с, 20 текстовых источников, 30 с полнотекстового поиска (p50, p95), объём данных. В конце скрипт удаляет свои
контейнеры, тома и данные и те образы, которые скачал сам. Сеть — около 610 МБ на одно скачивание.

## Риски и открытые вопросы

- R-002: без пространств граница продукта держится только экземпляром на продукт.
- Вторая база (SurrealDB) — вторая точка бэкапа и восстановления; RPO ≤ 2 ч надо держать и для неё.
- Безопасность по умолчанию слабая: нет пароля, `root:root`; на VPS — только за прокси и с паролем.
- Docling и Crawl4AI тянут ML-стек и Chromium: на VPS — нет.

## Вердикт и рекомендация

**C (контейнер целиком) — не брать:** дублирует блокнот, ломает R-002 в одном экземпляре, добавляет вторую базу и UI.

ссылок до/после. B — вернуться, если A не покроет Office и аудио. Числа RAM для C — после замера; решение — за владельцем.
