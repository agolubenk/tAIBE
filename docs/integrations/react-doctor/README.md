## Что это

- Статический анализ React: 287 правил (архитектура, производительность, корректность, безопасность, доступность,
  размер бандла). Правила живут в плагине **oxlint** `oxlint-plugin-react-doctor`; 100 из них — перенесённые правила
  oxlint `react/*` и `jsx-a11y/*` (README плагина).
- Три формы: CLI `react-doctor` (`npx react-doctor`), GitHub Action (`action.yml`: комментарий в PR, inline-замечания,
  порог `none|warning|error`), плагин oxlint для своего конфига.
- **Телеметрия:** CLI по умолчанию шлёт отчёты о сбоях и анонимную статистику (`@sentry/node` в зависимостях CLI);
  выключение — `--no-telemetry`. У плагина Sentry в зависимостях нет (`package.json` плагина, 14.11).
- **Лицензия — Modified MIT:** без письменного разрешения нельзя (1) использовать как данные или вход конвейера,
  который обучает или улучшает модель или ИИ-систему; (2) продавать как сервис. У нас это закрыто N-005 и R-072.
- Зрелость: 15,1 тыс. звёзд, релиз 2026-11-13.

## На что ложится в tAIBE

- Доски уже гоняют oxlint: `pnpm lint` = `vp check`, плагины `react` и `jsx-a11y`, `react/no-danger`,
  `react/rules-of-hooks`, `react/exhaustive-deps` — `error` (`boards/vite.config.ts:41-90`). Значит, около 100 правил
  react-doctor уже частично есть; новая ценность — около 187 своих правил (производительность, бандл, архитектура).
- Часть продукта — `boards/apps/web/` (frontend). Метрика — качество ревью: число настоящих находок на PR при
  доле ложных не выше порога.

## Варианты встраивания

| Вариант | Что берём | Куда | Цена | Эффект |
|---|---|---|---|---|
| A — плагин oxlint, отдельный шаг CI | `oxlint-plugin-react-doctor` (закреплённая версия) + свой конфиг только с его правилами; `oxlint --format json` | job `boards-ci` после `pnpm install`, отчётом (S23-2) | 1 devDependency; секунды oxlint (замер); без телеметрии | находки с префиксом `react-doctor/` — метка источника есть сама (N-005) |
| B — CLI или Action | `react-doctor` CLI / `action.yml` | своя задача CI | своя установка, Sentry, `playwright-core` в зависимостях CLI, комментарии в PR | то же плюс комментарий в PR |
| C — правила в общий `pnpm lint` | плагин в `boards/vite.config.ts` | локальный lint каждой сессии | сотни предупреждений в выводе каждой сессии — токены (замер) | агент чинит сразу |

## Замер (release, раннер GitHub)

Прогон на `board-agents` с закреплённой версией 0.9.23, без телеметрии, вывод JSON артефактом. Записать:

1. число находок всего и по правилам; топ-10 правил;
2. время шага на раннере;
3. выборку 20 находок — plan размечает «настоящая / ложная» по артефакту;
4. сколько находок дублирует уже включённые правила oxlint досок.

## Риски и открытые вопросы

- **N-005 и транскрипты.** Находки, которые агент увидел в выводе, попадают в транскрипт. Инструменты eval, которые
  читают транскрипты для улучшения агентов (антигены, геномы, S22-3), не должны брать строки `react-doctor/`. Проверка
  — в приёмке S23-4 (AC-015) и S22-3.
- Вариант C отвергнут заранее: шум в каждой сессии стоит токенов без замера пользы.

## Вердикт и рекомендация

**Предлагаю:** вариант A — плагин oxlint, отдельный шаг в `boards-ci`, только отчёт первую неделю. Решение «берём»
— после замера: если доля ложных в выборке 20 больше 30 % или настоящих находок меньше 5 на всё `apps/web`, — не
берём («на прежнем уровне — тоже отказ»). Порог — допущение для обсуждения в линзах.

**Адверсариальная проверка (возражения по линзам и ответы автора; независимые линзы — в PR):**

| Участник (линза) | Возражение | Ответ |
|---|---|---|
| корректность | 100 правил дублируют oxlint — двойные находки | замер п. 4; дубли выключаются в конфиге плагина |
| ресурсы | CLI тянет Sentry и Playwright | A — только плагин: без Sentry и Playwright |
| продукт | Action даёт комментарии в PR — удобнее | комментарии — шум на 140+ открытых PR; находки уходят в карточки (S23-4) |
