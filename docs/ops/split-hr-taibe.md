## Рамка (решения владельца 01–02.11, журнал `eval/data/decisions.jsonl`, `d-0211-*`)

1. **Только ноутбук.** Сервер не трогаем: VPS, стенд `d4dev.admin.hrhelper.space`, ops-консоль, бот очереди,
   WireGuard. Связь с сервером после разделения работает так же, как до него.
2. **Из HR уходят только `t-boards/` и `supertick-eval/`.** ИИ-сервисы `infra/` (консилиум, хаб, шлюз моделей,
   очередь, ops-консоль), `.claude/`, `.continue/`, `.agents/` остаются в HR и работают оттуда. Их чистка — позже,
   по частям.
3. **Слой в HR — копия.** Новые версии слоя делаются в tAIBE и переносятся в HR отдельным синком.

**Как устроено после разделения.** Код и данные `supertick-eval/` и `t-boards/app` живут в checkout'е tAIBE
(`~/Desktop/Development/tAIBE`). В checkout'е HR на их месте — символические ссылки, которые git HR не видит (они
скрыты в `.git/info/exclude`):

| Ссылка в HR | Куда ведёт | Зачем |
|---|---|---|
| `supertick-eval` | `tAIBE/eval` | Через этот путь работают геномы ролей, хуки-рефлексы, plist Нерва, `spawn_session.sh` и старые handoff |
| `eval` | `tAIBE/eval` | Капсулы и промпты ролей ссылаются на `eval/…` |
| `t-boards/app` | `tAIBE/boards` | MCP досок в хабе (`infra/scripts/dev-ai/mcp-t-boards.sh`) |
| `boards` | `tAIBE/boards` | Промпт роли «доски» ссылается на `boards/…` |

Сессии команды запускаются из HR теми же командами, что и раньше. Нерв и рой берут настройки пайплайна продукта с
досок. Если там выключить `nerveWakes`, Нерв перестанет будить сессии; шаг 3 это проверяет.

## Как работают скрипты

Каждый шаг — одна команда `bash ~/Desktop/Development/tAIBE/infra/scripts/split/<шаг>.sh`. Скрипт сам проверяет
условия, всё пишет в журнал `~/Backups/split-2026-11-02/LOG.md` и заканчивается одним из кодов:

| Код | Последняя строка | Что делает исполнитель |
|---|---|---|
| `0` | `ГОТОВО. Следующая команда: …` | Сразу выполняет названную команду |
| `3` | `СТОП: <причина>` | Ничего не исправляет сам. Показывает владельцу строку «СТОП» и ждёт ответа |
| `4` | `ЖДЁМ: <действие владельца>` | Передаёт владельцу строку «ЖДЁМ» и продолжает только после его ответа |
| `1` или другой | ошибка | Как `3`: показать вывод владельцу и ждать |

Скрипт можно запускать повторно: сделанное он пропускает. После СТОП, когда владелец ответил, тот же шаг
запускают ещё раз. Это касается и 5b: если ссылки уже стоят, переключение не повторяется, шаг сразу переходит к
запуску Нерва и проверкам.

**Переменные-разрешения** ставятся перед командой, и только когда владелец прямо сказал это в ответ на
конкретный СТОП. Например: `SPLIT_OWNER_OK_DUMP=1 bash …/2-backup.sh`.

| Переменная | Что разрешает |
|---|---|
| `SPLIT_OWNER_OK_BRANCHES=1` | Продолжить, хотя ветки HR меняют `supertick-eval/` или `t-boards/` (шаг 1) |
| `SPLIT_OWNER_OK_DUMP=1` | Продолжить без дампа базы досок моложе суток (шаг 2) |
| `SPLIT_OWNER_OK_799=1` | Продолжить, хотя коммита `799fae6` нет в бандлах (шаг 2) |
| `SPLIT_OWNER_OK_WAKES=1` | Продолжить с выключенным на доске `nerveWakes` (шаг 3) |
| `SPLIT_OWNER_OK_KILL_TAPS=1` | Окна сессий уже закрыты, но остались их процессы `nerve.py tap`. Шаг 5a их завершит |

## Правила для исполнителя

- Только эти скрипты и команды ниже. **Не править файлы руками**, не обходить СТОП, не придумывать шаги.
- **Ничего не удалять** и не запускать `rm -rf`, `git reset --hard`, `git clean`, `git stash`, `--force`.
- **Не пушить в `main` HR и не вливать PR.** Вливает только владелец.
- **Не трогать сервер:** ни `ssh`, ни `bundle.sh`, ни `install.sh`.
- Команды выполнять в **bash**, а не в zsh.
- Секреты в чат и журнал не выводить.

## Шаг 0. Клон tAIBE (исполнитель, один раз)

```bash
mkdir -p ~/Desktop/Development
```

Папка `~/Desktop/Development/tAIBE` у владельца уже может быть. Тогда её используют, если это клон
`agolubenk/tAIBE` без незакоммиченных правок; иначе клонируют заново:

```bash
T=~/Desktop/Development/tAIBE; if [ ! -e "$T" ]; then git clone https://github.com/agolubenk/tAIBE.git "$T"; elif git -C "$T" remote get-url origin 2>/dev/null | grep -q 'agolubenk/tAIBE'; then [ -z "$(git -C "$T" status --porcelain)" ] && echo "есть чистый клон tAIBE — используем" || echo "СТОП: в $T незакоммиченные правки — спросить владельца"; else echo "СТОП: $T — не клон agolubenk/tAIBE — спросить владельца"; fi
```

Если строка начинается со «СТОП», остановиться. Иначе:

```bash
cd ~/Desktop/Development/tAIBE && git fetch origin && git switch board-agents && git pull --ff-only origin board-agents && git log --oneline -1 && ls infra/scripts/split/
```

Ожидаемо: последний коммит `board-agents` и в папке 12 скриптов. Иначе — СТОП. Если `git switch` или `git pull` не
проходят (например, клон был на другой ветке с локальными коммитами), тоже СТОП и вопрос владельцу.

## Почему синк блокнота на паузе

Синк отправляет на сервер файлы, которые числит git HR (`git ls-files`), а исчезнувшие удаляет из блокнота. После
разделения git HR больше не числит `t-boards/*.md` (там спецификация досок) и `supertick-eval/**/*.md`. Включённый
синк удалил бы эти документы из блокнота на сервере. Включать его — только по решению владельца:
- либо синк из двух корней, HR и tAIBE (M3 дорожной карты);
- либо принять потерю этих документов в блокноте.

Синк SSR (`ssr-sync.mjs`) руками не запускать по той же причине.

## Чего не делать до следующих шагов дорожной карты

- **Не собирать и не выкатывать образ досок** (`deploy/vps/bundle.sh`). `t-boards/app` теперь ведёт в tAIBE, а
  там перенумерованные миграции 0078–0081. Стенд переключается отдельно, с бэкапом
  (`process/TRANSFER.md`, раздел «Стенд d4dev»; дорожная карта, M6).
- **Не вливать в HR ветки, которые меняют `supertick-eval/` или `t-boards/`** (список — шаг 1). Мёрж такой ветки
  вернёт настоящие папки на место ссылок.
- `tAIBoard_and_Eval` (старый вложенный клон tAIBE в HR, из git HR удалён 01.11) не переносится. Он остаётся на
  месте, его снимок — в бэкапе шага 2. Что с ним делать, решает владелец.
- Worktree `t-boards/worktrees/fix/tb-notion-5xx-retry` после переноса лежит в бэкапе. Git в нём заработает после
  `git -C ~/Backups/split-2026-11-02/moved/t-boards/app worktree repair`. Коммит `799fae6` и так есть в бандле шага 2
  и в ветке `rescue/*`.
- Старые worktree HR держат свои копии этих папок, пока не подтянут `main`. После этого они работают через
  основной checkout: команда наследника идёт через `git rev-parse --git-common-dir`.
