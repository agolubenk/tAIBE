# Закрытое — оглавление

> **Канон закрытого** — вторая половина двойного закрытия (статус карточки tAI-Boards + запись здесь). Отвечает на
> «делали ли уже, как решили, каким коммитом» до начала работы; его читают ИИ-консилиум (скептик, планировщик,
> ревью — `[sources.done_md]` в `infra/ai-council/config.toml`) и RAG (`--type done_entry`).

## Как найти прошлое решение — от быстрого к долгому

1. `grep -rn "<ID|коммит|часть заголовка>" docs/plans/done/` — всегда актуален: ID трека или карточки, короткий SHA,
   ключ карточки tAI-Boards, тег (`#bug`, `#decision`).
2. `python3 .claude/scripts/rag_query.py "<тема>" --type done_entry --full` — по смыслу, одна запись = один документ.
   Индекс локальный: после pull и для новых файлов — `python3 .claude/scripts/index_rebuild.py --type done_entry`.
3. Таблица модулей ниже → файл → раздел. Файлы целиком не читать — только найденную запись.
4. Ход реализации досок до переноса — `boards/docs/impl-progress.md` и `boards/docs/impl/`; история механизмов
   пайплайна — `eval/pipeline/PIPELINE.md`.

## Как добавить запись

1. **Файл** — модуль, где живёт основной код решения. На стыке модулей — первый модуль карточки t-boards (поле
   модулей), без карточки — модуль с большей частью изменённого кода; в записи — «см. также `done/<модуль>.md`».
   Префикс ID модуль не определяет: колонка «ID в записях» описывает, что уже лежит в файле.
2. **Место** — раздел «Журнал» файла: подраздел `### YYYY-MM` месяца закрытия (новый месяц — выше предыдущего),
   запись — в конец месяца.
3. **Формат — одна строка, ориентир ≤ 400 символов:**
   `- **<ID> — <заголовок>** (YYYY-MM-DD · \`<sha>\` · <ключ t-boards, напр. ЗАДАЧИ-123>) — что сделано; для решения — почему так. #тег`
   Теги из словаря: `#bug` `#security` `#perf` `#data` `#ux` `#infra` `#decision`; закрытая карточка «Ошибок» —
   обязательно `#bug`. Подробности — в коммите и карточке, не здесь. Формат «Журнала» проверяет `python3 infra/scripts/misc/done-index.py --check`.
4. **Новый модуль** — файл `done/<kebab-case>.md` по образцу (шапка «Область / Код и знания», «Журнал»), затем
   `python3 infra/scripts/misc/done-index.py`.
5. **Рост** — файл модуля больше 400 записей или 300 КБ: закрытые годы — в `done/<модуль>/<год>.md`, ссылка из шапки
   (`python3 infra/scripts/misc/done-index.py --check` падает, пока лимит превышен).
6. **Индексы** — RAG-индекс локальный (в `.gitignore`): Stop-хук обновляет изменённые записи, после pull и для новых
   файлов — `python3 .claude/scripts/index_rebuild.py --type done_entry`.

## Поток закрытия в tAIBE — один PR записей в сутки (SE-61, 2026-11-13)

Замер: с 06.11 по 13.11 из 104 PR tAIBE 15 содержали только записи done (13.11 — 8). Запись вместе с кодом была у 5.
Каждый такой PR — ветка, проверки, вливание Контролем и ходы сессий. Записи дописываются в конец одного раздела,
поэтому параллельные PR конфликтуют.

| Шаг | Кто | Что |
|---|---|---|
| 1 | автор | после вливания своего PR — строка роли «план» через Нерв: `done #<n> <КЛЮЧ> — <что сделано>`. Свой PR записей не открывает, `close_task` не просит |
| 2 | план (роль 2) | единственный, кто пишет в `done/`: дописывает запись в ветку дня `docs/done-<YYYY-MM-DD>` (дата первой строки). Нет строк за день — нет ни ветки, ни PR |
| 3 | план | по сигналу крона координатора 20:50 — PR `docs(done): <дата> — <ключи>` с `[skip ci]`, «PR #n собран» Контролю. Своего таймера у плана нет (TEAM-0 §10.6). Линзы не нужны: это механика, не решение |
| 4 | Контроль | вливает PR дня после `done-index.py --check` |
| 5 | план | одна пакетная заявка `close_task` (`taskIds`, `doneRef` = PR дня, TB-108): одно «да» владельца закрывает все карточки дня |

Карточка до закрытия стоит в своей колонке, до суток. Записи в PR с кодом в tAIBE не пишутся: они конфликтуют с PR дня.
