## Правила

- **R-1. Один процесс** (Р3 = А). Проход: общая часть (бюджет, system, hub, очередь — один запрос `items` и один
  `checks`), затем GitHub каждого продукта с `active: true` (транскрипты продукта — Ф2b). Сбой одного продукта пишется в его
  `errors` и не мешает остальным. Продукт по умолчанию идёт первым.
- **R-2. Продукт процесса** — один разбор для `tap`, `emit`, `status`: флаг `--product <slug>` → env
  `TAIBE_PRODUCT` → `default_product`. При фолбэке на `default_product`, если включён другой продукт, команда
  печатает одну строку «продукт не задан — продукт по умолчанию hr-helper» (stderr): ошибка видна, живые Monitor ролей
  HR не падают, а пока других продуктов нет, строка не будит их зря.
  Пусковые файлы tAIBE пишут флаг явно: `nerve.py tap <роль> --product taibe`. Env не заменяет флаг: сессия после
  `--resume` без `--settings` может потерять геном (предположение, не проверено).
- **R-3. Файлы продукта.** `tap`, `emit` и `status` читают журнал и курсор из папки продукта, а пульс, `mode.json`
  и `cycle.json` — всегда из `eval/nerve/state/`. Иначе `tap` роли-наблюдателя tAIBE сразу печатает «НЕРВ МОЛЧИТ»
  (`nerve.py:213-214`) и не видит паузу. Пульс новый `tap` читает из файла `state/heartbeat` (25 Б, пишется каждым
  проходом, `nerve.py:129-130`), а не из `state.json` (0,96 МБ каждые 15 с, пик 20 МБ у наблюдателя); демон пишет
  оба, так что старые `tap` работают. Курсор `tap-<роль>.json` пишется через свой tmp-файл процесса. Исключающий
  `flock` не ставится: при передаче роли tap предшественника и наследника живут одновременно (сторож снимает
  предшественника, только когда у наследника есть tap).
- **R-4. Seed нового продукта.** Пока в `state.json` продукта нет отметки `seeded`, его проход пишет журнал и никого
  не будит. Отметка ставится после первого прохода без сбоя GitHub. Ни ранний `emit`, ни сбой `gh` в первом проходе
  не отдают открытые PR будилками. `emit` в невключённый продукт отказывает.
- **R-5. События аккаунта** (`budget.warn`, `limit.hit`, `limit.resume`) пишутся в журнал **каждого** активного
  продукта с тем же ключом. Порог 80 % считается один раз — по аккаунту, то есть по обеим командам.
  - Роли HR получают их как сейчас (инвариант).
  - В tAIBE `limit.hit` и `budget.warn` — только `coord`; `limit.resume` — живые роли tAIBE (остановленную лимитом
    роль больше никто не разбудит).
  - Почему не всем: каждая будилка стоит денег окна. Линза ресурсов: медиана работы после будилки $1,40 у
    `budget.warn` и $1,87 у `limit.resume` (предположение по всплескам 20 мин после события); при 12 ролях один
    `budget.warn` — около $17, 11 % окна $148,8, уже после отметки 80 %. Адресаты по активности (транскрипт менялся за
    10 мин) для обоих продуктов — отдельная карточка, она меняет и будилки HR.

  `owner.stop` — во все журналы, адресат `all`. `nerve.error` и `sys.*` (Mac, хаб) — в журнал продукта по умолчанию,
  роли `release`, как сейчас; `nerve.error` источника продукта — в журнал этого продукта.
- **R-6. Продукт пункта очереди.** Сначала поле `product` документа (продукт пункта выбирает владелец; v2-lite #95,
  `oq_docs.product`). Поля нет (очередь до v2-lite) — по `queue.match`: id пункта содержит `-taibe-` (`m-taibe-79`,
  `d-taibe-…`) → `taibe`, иначе продукт по умолчанию. Пусковые файлы ролей tAIBE требуют `-taibe-` в id каждого
  своего пункта. По `cwd` сессии-автора не маршрутизируем: сессия HR в worktree tAIBE ждёт ответ сама, а по папке он
  ушёл бы команде tAIBE. Внутри продукта — его `source_roles`, как сейчас.
- **R-7. Входящие** (`owner.inbox`) — одному координатору: продукта из поля `product` входящего, если его задал
  владелец (07.11: входящее tAIBE `i-20261105-144934-67e7` двое суток лежало у координатора HR); `owner.stop` такого
  входящего — только в журнал его продукта. Поля нет — координатору продукта по умолчанию, как сейчас. У входящего нет
  сессии-автора (его создают владелец и бот), а текст — данные третьих лиц, по нему не маршрутизируем. Входящее
  tAIBE координатор HR передаёт: `nerve.py emit coord "входящее <id>" --product taibe --kind owner.inbox`. Будить
  обоих дороже: проигравший платит полный ход за 409.
- **R-8. Роль и продукт у сессии.**
  - `lineage_reap.ROLE_RE` читает и `genome/<slug>/<роль>.json` и отдаёт пару (продукт, роль); сейчас путь
    `genome/taibe/boards.json` не совпадает (проверено линзой).
  - `scan` выбирает текущую сессию роли по паре (продукт, роль): сейчас держатель роли одного продукта стал бы
    кандидатом на уборку через 24 ч из-за роли другого (`lineage_reap.py:144-152`).
  - `lineage_retire.TAP` принимает флаги в любом месте (`tap --product taibe boards`, `tap boards --product taibe`)
    и сверяет продукт.
  - `team_status.py` уже делит роли по корню checkout (`--cwd`); роли HR работают в `HR_Helper-v2`, ролей tAIBE
    пока нет.
  - Ключ реестра в первом сообщении остаётся `<роль>`: продукты делит `project_dir`.
- **R-9. Транскрипты продукта.** `map_roles` читает `project_dir` и `project_dir-worktrees-*` (сессии в worktree
  получают свою папку проекта, `sources.py:231`), иначе события аккаунта уходят только `coord`.
- **R-10. Запуск.** `spawn_session.sh --product <slug>` — и в `--launch`, и в `--handoff`: геном, пусковые файлы и
  рабочая папка (`repo_root`) продукта. Без флага — `TAIBE_PRODUCT` из env (сессия-наследник берёт продукт
  предшественника), затем продукт по умолчанию. Скрипт экспортирует `TAIBE_PRODUCT` в пусковую команду. Новый
  `--dry-run` печатает команды и ничего не делает: без него `--launch` чинит Нерв (`:265`) и пишет линию (`:183`).
- **R-11. Включение продукта.** `instances/taibe.json` идёт с `active: false` до Ф4. Неактивный продукт проход не
  обходит, `owner.inbox` и ответы ему не идут. Так новый демон, который поднимет любой `kickstart` после `git pull`
  (`team_status.py:179-182`), не пишет событий в журнал, который никто не читает.
- **R-12. `nerveWakes`** в Ф2 общий для всех продуктов, как сейчас (`nerve.py:41`, ключ доски одной установки).
  Свой переключатель продукта — когда у продукта будет свой ключ доски (M2 R-2), вне OPS-25.
- **Сквозные инварианты:** роли HR будятся как до OPS-25 — с одним исключением R-9: сессии HR в worktree
  (`<project_dir>-worktrees-*`) теперь тоже получают события аккаунта (07.11: +1 роль, `backend`; ≈ +$1,4 на
  `budget.warn`), без этого роль, остановленную лимитом в worktree, никто не будит; мёрж в `board-agents` прод не деплоит; в репозиторий HR
  OPS-25 не пишет; секретов в `instances/` и `state/` нет (`secret_cmd`, как сейчас).
