> **Статус (2026-11-13):** 🔲 спека v1.1 (правки линзы «корректность и отказы» на 976b6ee3b), кода нет. Развилки Q-1 и Q-2 — пункт владельца `d-taibe-se71-codemode-1311`

> (SE «supertick-eval»), источник — входящее владельца `i-20261111-201549-dc60` (11.11, critical).

## Проблема

Владелец, 13.11: в песочнице разбираются все инструменты и правила их вызова, там же автоматически делаются сами
вызовы, а модели возвращается только ответ: что задействовать и что есть. Это уход от прямого вызова инструментов
моделью.

Внешний принцип (предположение: reel не открыт, Instagram требует входа; источник — слова владельца):
Cloudflare «Code Mode» (09.2025) и Anthropic «Code execution with MCP» (11.2025). Модель пишет короткий код против
API инструментов, песочница его исполняет, промежуточные данные в окно модели не попадают.

## Пользователи и сценарии

Пользователи — роли Т3 tAIBE (координатор, план, авторы, Контроль). Харнессы: Claude Code (песочница context-mode),
Codex, Continue, Kimi — через свой shell (R-035 в `boards/docs/t-boards-spec.md`).

- **S-1. Состояние PR.** Автору, линзе или Контролю нужны голова, CI и вердикты на эту голову. Рецепт `pr <n>`
  возвращает 3–6 строк вместо `gh pr view` + `gh pr checks` + чтения комментариев.
- **S-2. Разбор очереди.** Координатору нужны открытые пункты своего продукта и ответы владельца с момента X. Рецепт
  `inbox` возвращает id, заголовок, возраст и статус агента, без текста заметок.
- **S-3. Старт сессии и следующая карточка.** Рецепт `brief <роль>` собирает свой work state, work state на доске,
  `queue_focus --plan` и свои пункты очереди в одну сводку.
- **S-4. Свободный скрипт.** Агенту нужна редкая цепочка, например «карточки строки плана в `in-review` без ссылки
  на PR». Агент пишет 5–15 строк Python против клиента и печатает только итог.
- **S-5. Шаг сессии одной записью** — только если владелец разрешит запись (Q-2). Рецепт `step "<текст>"` пишет шаг
  и в claude-mem, и на доску.

## Модель

- **Клиент `eval/tools/codemode/`** — stdlib Python ≥ 3.10. Модули:
  - `http` — общий транспорт `board` и `queue`. Метод GET — константа, а не параметр: другого метода транспорт
    отправить не умеет. Тайм-аут — 2 с на вызов;
  - `board`: чтение t-boards с ключом и меткой `session` той же сессии. Маршрут (хаб `127.0.0.1:3050/mcp` или REST
    t-boards) выбирается в плане — Q-3. Если выбран хаб: JSON-RPC идёт через POST, поэтому `board` принимает только
    имена инструментов чтения из белого списка (`get_*`, `list_*`, `forest_get_*`, `forest_list_*`, `search`);
  - `queue`: HTTP API очереди владельца, токен как у `queue_focus.py` (env или `secret_cmd` из
    `instances/_shared.json`), токен по продукту (OPS-51);
  - `mem`: `~/.claude-mem/claude-mem.db` только на чтение, как прокси TB-113 (`boards/deploy/vps/mac/card-memory-db.mjs`).
    URI `file:…?mode=ro`, без `immutable=1`: при живом писателе он даёт несогласованное чтение. Тайм-аут блокировки
    — 0,5 с (`sqlite3.connect(timeout=0.5)`, по умолчанию 5 с). Перед первым запросом сверяются колонки, как
    `schemaFits` в прокси. Поиск FTS5 — только по формам ключей TB-113 (`memory-keys.ts`: id карточки, ключ доски,
    id пункта очереди), фраза в кавычках. HTTP воркера claude-mem 13.11 не ответил за 3 с (проверено), на него не
    опираемся;
  - `gh`: `gh … --json` подпроцессом только по белому списку (R-1).
- **Рецепты** — `python3 -I eval/tools/cm.py <рецепт> [аргументы]`: `pr`, `inbox`, `brief`. По умолчанию — текст;
  `--json` — для скриптов.
- **Свободный режим** — `python3 -I eval/tools/cm.py run - <<'PY' … PY`. Скрипт получает объекты `board`, `queue`,
  `mem`, `gh` только с методами чтения. Печать — через `print`.

## Правила

- **R-1. Свободный режим только читает.** (Q-2.) В Python нет закрытых методов, поэтому «нет записи» значит три
  свойства транспорта, а не набор публичных методов:
  1. `http` отправляет только GET: метод — константа. Хаб (если выбран в Q-3) — только инструменты чтения из
     белого списка;
  2. `mem` открывает базу с `mode=ro`;
  3. `gh` — белый список подкоманд: `pr view|checks|list`, `run list|view`, `api` только GET. Флаги `-X`/`--method`,
     `-f`/`-F`/`--field`/`--raw-field`, `--input` отклоняются: `gh api -f k=v` без `-X` сам переходит на POST.

  **Модель угроз.** R-1 защищает от случайной записи из скрипта, а не от умышленного кода агента. У агента с shell
  уже есть `secret_cmd` и прямые вызовы, их охраняет merge-guard. Code mode новых прав не даёт и не отнимает.
- **R-2. Запись — только именованным рецептом** (если владелец разрешит): команда фиксирована, хук merge-guard
  (matcher `Bash`) видит её так же, как прямой вызов инструмента, и проверяет имя сессии и правила вливания.
- **R-3. Потолок вывода.** Рецепт — до 1000 символов, свободный режим — до 4000. Обрезка — по символам на границе
  строки (срез байтов рвёт кириллицу в UTF-8), с меткой «…+N строк: `--json > файл`».
- **R-4. Продукт.** Видимость режет токен продукта (OPS-51). Фильтр клиента — второй рубеж: tAIBE — `-taibe-` в id;
  HR — нет префикса другого продукта (`namespaceOf`).
- **R-5. Секреты.** Токены — из env или Keychain через имеющийся `secret_cmd`, в вывод не попадают. Сеть — только
  `127.0.0.1`, URL очереди и GitHub.
- **R-6. PII.** Заметки владельца и тексты входящих не печатаются: id, заголовок (≤ 80 символов), статус, возраст
  (урок `oq-note-echo`).
- **R-7. Отказ — два вида ошибок.** Code mode не блокирует работу.
  - **Отказ источника** (сеть, 401/5xx, тайм-аут, `database is locked`, нет файла базы, нет `-shm` у базы в WAL после
    перезагрузки, схема изменилась): одна строка «<источник>: недоступно (<причина>)», код 3, без traceback. Агент
    повторяет прямым вызовом только этот источник.
  - **Частичный отказ:** рецепт с несколькими источниками (`brief`) печатает данные живых источников и по строке на
    упавший, код 3.
  - **Ошибка в скрипте агента** (`NameError`, `KeyError` в его коде): traceback и код 1. Без traceback агент не
    починит скрипт.
  - **Бюджет времени:** 2 с на вызов источника и общий дедлайн рецепта 3 с. Источник, который не ответил к дедлайну,
    — частичный отказ.
- **R-8. Только stdlib** (правило `eval/`). Новая зависимость — отдельное решение.
- **R-9. Правило в геноме — через A/B.** Вариант B генома роли: «Если нужно ≥ 3 чтений доски, очереди или памяти либо
  фильтр списка — используй code mode». Вводится через evolve после замера, не сразу всем.

## Приёмка

- **AC-1.** `cm.py pr 172` печатает голову, сводку проверок (pass / fail / pending) и по строке вердикта на линзу для
  текущей головы. Вывод ≤ 1000 символов, время ≤ 3 с (дедлайн R-7). Юнит-тест на фикстурах JSON.
- **AC-2.** `cm.py inbox --product taibe` печатает открытые пункты (id, заголовок, возраст, `agentStatus`) без
  полей `note` и `inbox.text`. 20 пунктов ≤ 1000 символов.
- **AC-3.** `cm.py brief plan --product taibe` заменяет цепочку старта (`work_state_read` + `forest_list_work_state`
  + `queue_focus.py --plan` + `oq_list`). Вывод ≤ 1500 символов.
- **AC-4 (R-1).** Тесты:
  - `http` на подменённом `urlopen` отправляет только GET; хаб — отказ на имени инструмента записи;
  - `gh` отказывает на `pr merge`, `pr comment`, `api -X POST`, `api --method PATCH`, `api -f k=v`, `api --input`;
  - `mem` на фикстуре SQLite не выполняет `INSERT`: `attempt to write a readonly database`;
  - R-3: обрезка на границе строки не рвёт кириллицу.
- **AC-5 (R-7).** Тесты на оба вида ошибок: отказ источника (тайм-аут, 503, нет файла, `database is locked`, схема
  без нужной колонки) → одна строка и код 3; `NameError` в скрипте агента → traceback и код 1. `brief` при одном
  упавшем источнике печатает остальные и код 3, укладывается в 3 с при спящем источнике.
- **AC-6. Замер.** База и итог — `eval/tools/context_audit.py` (строки «результат:mcp:…» и «результат:Bash»). A/B на
  одну неделю в tAIBE. Цель группы B: −30 % токенов результатов MCP на роль в день и −50 % вызовов `gh pr view`; ходов
  на карточку не больше, чем в группе A (`wake_anatomy.py`).
- **AC-7.** Тесты — `python3 -I -m unittest` на фикстурах без сети, в `eval-ci` / `layer-ci`.

## Не входит

- Свой MCP-сервер или отдельная среда исполнения (изолят Deno). Песочница с shell уже есть в каждом харнессе.
  Вернуться к вопросу, если появится харнесс без shell.
- Правки claude-mem: это внешний плагин. Эхо `work_state_write` остаётся. Смягчение — рецепт `brief` читает список
  сам, и агенту не нужен полный `work_state_read`.
- Замена ToolSearch и загрузки схем.
- Команда HR (Lavaeon) — после A/B в tAIBE. Клиент не привязан к продукту, вариант генома переносит evolve.

## Открытые вопросы

- **Q-1 (владелец, `d-taibe-se71-codemode-1311`).** Что строим первым: рецепты, свободный режим или оба?
  Рекомендация — оба на одном клиенте: сначала клиент и рецепты `pr`, `inbox`, `brief`, затем свободный режим.
- **Q-2 (владелец, тот же пункт).** Пишет ли код из песочницы? Рекомендация — свободный режим только читает. Если
  владелец разрешит запись — только именованными рецептами под хуком (R-2), первый из них `step` (S-5).
- **Q-3 (план, не владелец).** Чтение доски через хаб (JSON-RPC MCP) или через REST t-boards. Решает линза
  «простота» в плане реализации.
