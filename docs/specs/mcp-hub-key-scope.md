## 2. От чего защищает разделение ключа, а от чего нет

- **Защищает от утечки ключа с машины:** ключ попал в лог, транскрипт, вставку в чат или модель. Сейчас такая утечка
  открывает все 3 продукта до отзыва ключа. Ключ агента открывает их на 24 ч.
- **Не защищает от локального процесса.** Хаб без auth, и любой процесс пользователя зовёт его на `127.0.0.1:3050`
  с любым срезом. Хук не читает ключ, но может позвать хаб. Пункт приёмки «хуки не видят ключ хаба» выполняется
  буквально и мало значит, пока у хаба нет auth. Auth хаба — отдельная задача (OPS-21), в эту спеку она не входит.

## 4. Рекомендация

**D сейчас, затем B.** A отклонён по цене: +27 тыс. токенов на сессию с двумя продуктами и переименование
инструментов в двух репо. Защита у A та же, что у B, пока хаб без auth. C отклонён: он расширяет модель области во
всём API ради исключения одного воркспейса.

1. **D (без кода, шаги владельца).** Владелец выпускает новый ключ со сроком 30 дней и кладёт его в Keychain тем же
   именем. Затем `mcp-hub.sh restart hub`, проверка `whoami` и `list_workspaces` в двух клиентах, отзыв старого ключа.
   Откат: прежний ключ не отзывается, пока проверка не прошла; при сбое ключ возвращается в Keychain, затем
   `restart hub`.
2. **B (код, PR с ≥ 4 линзами).** `POST /api/agent-identity/session` принимает `workspaceId`. Ключ агента получает
   `metadata.workspaceId`, а агент — одно членство в этом воркспейсе. MCP берёт воркспейс из конфигурации среза: одна
   переменная `KANEO_MCP_WORKSPACE` на процесс, без маршрутизации по вызову. Без переменной MCP работает как сейчас.
   Ключ владельца остаётся у хаба только для выпуска агентов.
3. **Позже, отдельными карточками:** TB-96 (`access=read` для ключей с областью), auth хаба (OPS-21).

## 6. Приёмка

- D: `whoami` через хаб — новый ключ, `list_workspaces` — ожидаемые продукты, старый ключ отозван (запрос с ним → 401).
  Шаги и откат — в пункте очереди, `after` с откатом.
- B: интеграционные тесты API — ключ агента с `workspaceId` видит только этот воркспейс (чужой → 404), без
  `workspaceId` поведение прежнее, ключ с областью не выпускает агента шире своей области. Тест MCP —
  `KANEO_MCP_WORKSPACE` уходит в запрос выпуска.
- Хуки не берут ключ хаба: уже так (`pipeline_settings.py`), тест остаётся зелёным.
