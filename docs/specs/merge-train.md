## Что строим

### Ф1. Проверка базы перед `pr.quorum` (S)

- При кворуме Нерв делает один запрос `gh pr view --json mergeable,mergeStateStatus,baseRefName`.
- Если `mergeable = CONFLICTING`, Нерв шлёт событие `pr.conflict` автору (`author_role`) вместо `pr.quorum`.
- Если `baseRefName` — не ветка по умолчанию, PR стоит в стопке. Статус — «ждёт #N», `pr.quorum` не уходит. После
  мёржа базы и rebase PR проверяется заново на новой голове.
- `UNKNOWN` (GitHub ещё считает): повтор на следующем проходе, не чаще одного запроса за проход.

### Ф2. Документ релиза (M) — SE-59 п. 3

- Файл `eval/nerve/state/products/<slug>/release.json` — состояние, в git не идёт. Размер ≤ 2 КБ, поле `version`
  растёт при каждой записи. Запись атомарная: временный файл и `os.replace`.
- Писатель один — Нерв. Другие роли пишут в документ только через команды Нерва:
  - `nerve.py release show [--if-version N]` — чтение; без изменения версии — пустой ответ;
  - `nerve.py release decide <PR> hold|first|skip|resume "<причина>"` — решения Контроля (роль 5);
  - `nerve.py release ready <PR> <sha>` — автор отмечает голову готовой к линзам (Ф4).
- Строка PR: номер, голова, вердикты на голове, `mergeable`, «ждёт #N», решение Контроля, итог деплоя.
- Порядок — по времени кворума, решения Контроля меняют его. Координатор порядок не пишет: сообщение «#A → #B»
  заменяет `decide … first`.
- Документ — кэш. Источник правды — GitHub и комментарии PR. Битый или пропавший файл Нерв собирает заново за
  один полный проход.

### Ф3. После мёржа: деплой и проба прода (M) — только где мёрж = деплой

- Блок `deploy` в `instances/<slug>.json`:
  - `workflow` (у HR — `deploy-contabo.yml`), `probes` (`/api/v1/health/ready`, `/`, `/login`);
  - `timeout_min: 120`, `start_wait_min: 10`.
  - У tAIBE блока нет: мёрж в `board-agents` деплой не запускает, стенд d4dev выкатывает release вручную.
- После мёржа Нерв ищет прогон workflow для коммита мёржа. Опрос — раз в 60 с с ETag (ответ 304 не тратит лимит
  GitHub).
- Если за `start_wait_min` прогона нет, деплой не нужен (`paths-ignore`: документы, `.claude/**`). Итог «без
  деплоя».
- Прогон кончился: три пробы, по одному GET без редиректов, тайм-аут 10 с. Итог пишется в документ и уходит одним
  событием: зелёное — `coord` (digest), красное — `release` (nervous) с причиной.
- Стоп по `timeout_min` — красное событие «деплой не кончился».

## Отказы

- **Нерв лежит.** Работает ручной путь как сейчас: Контроль смотрит `gh pr view`. Документ не используется.
- **GitHub отвечает ошибкой.** PR остаётся в прежнем статусе, повтор на следующем проходе. Это поведение
  `poll_github` (`_raise_fails`).
- **Две записи сразу.** Писатель один, команды `release decide/ready` кладут заявку в файл входа. Нерв применяет
  заявки по порядку в своём проходе.
- **Проба красная из-за сети Mac.** Событие говорит, какая проба и какой код. Решает Контроль, автоотката нет.
