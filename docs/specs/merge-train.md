## Отказы

- **Нерв лежит.** Работает ручной путь как сейчас: Контроль смотрит `gh pr view`. Документ не используется.
  `release show` печатает возраст пульса (`state/heartbeat`); после 2 пропущенных проходов строки помечены «устарели».
- **`release.json` битый или удалён.** Нерв собирает документ заново и проигрывает `release.decision` из журнала
  (Ф2): PR с `hold` остаётся на `hold`, и следующая сессия Контроля его не вливает. Без журнала решение терялось бы:
  в GitHub оно не пишется.
- **`github.merge` нет или он битый.** Режим — `owner_item` (Ф2, п. 2 «Что снимается»): ошибка конфигурации ведёт к
  m-пункту, а не к мёржу Контролем.
- **`UNKNOWN` не проходит.** Через 30 мин — событие координатору (Ф1), `pr.quorum` не уходит.
- **GitHub отвечает ошибкой.** PR остаётся в прежнем статусе, повтор на следующем проходе. Это поведение
  `poll_github` (`_raise_fails`).
- **Две записи сразу.** Писатель один, команды `release decide/ready` кладут заявку в файл входа. Нерв применяет
  заявки по порядку в своём проходе.
- **Проба красная из-за сети Mac.** Событие говорит, какая проба и какой код. Решает Контроль, автоотката нет.

## Приёмка

Замер — тот же подсчёт по журналу Нерва, окно ≥ 5 ч с ≥ 5 влитыми PR, до и после.

1. Событий Контролю на влитый PR — ≤ 1 в медиане (сейчас 2,5, p90 8).
2. Ручных сообщений с порядком «#A → #B» — 0 (сейчас 12 за 5,2 ч).
3. CI, конфликт и стопка видны до `pr.quorum`. Тесты `unittest` на ответы `gh` из фикстур:
   - CI `pending` и `failure` при трёх approve — `pr.quorum` нет (тесты карточки SE-86);
   - `CONFLICTING` и `UNKNOWN`; `UNKNOWN` дольше 30 мин — одно событие `pr.mergeable_unknown` координатору;
   - `CONFLICTING` после чужого мёржа при прежней голове — событие `pr.conflict`;
   - база — не ветка по умолчанию;
   - база сменилась после squash, голова прежняя — событие `pr.rebase`, вердикты прежней головы помечены «старые»;
   - третий approve после чужого мёржа при прежней голове — свежий `gh pr view` даёт `CONFLICTING`, уходит
     `pr.conflict`, а не `pr.quorum`;
   - пустой список проверок у головы при трёх approve — `pending`, `pr.quorum` нет.
4. Режим и пути (S60-2), тесты на фикстурах `instances/`:
   - `github.merge` нет, режим неизвестен или блок не разбирается — строка «m-пункт»; HR — «m-пункт»;
   - PR с файлом из `owner_paths` (`.claude/`, `boards/deploy/vps/install.sh`, миграция, `instances/`) в режиме
     `control` — «m-пункт» с названным путём;
   - `changedFiles` больше длины `files` — «m-пункт»;
   - пересборка удалённого `release.json` с `release.decision hold` в журнале — PR на `hold`; с `hold`, затем
     `resume` — PR без решения; `hold` после новой головы остаётся;
   - PR переименовывает файл из `.claude/` (`changeType = RENAMED`, `previous_filename` в `owner_paths`) — «m-пункт»;
     REST `pulls/<n>/files` не ответил — «m-пункт»;
   - PR добавляет файл в `.github/workflows/` — «m-пункт».
5. HR: у каждого мёржа в документе есть итог: «деплой + 3 пробы», «выкачен прогоном `<sha>`» или «без деплоя». Тест на
   отменённый ждущий прогон и прогон-потомок. Ни одна роль не держит свой опрос деплоя.
6. Действий владельца на релиз не больше, чем сейчас. Если владелец выберет пакетное «да» — одно на пачку.
