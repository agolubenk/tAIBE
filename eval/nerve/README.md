# Нерв — нервная система команды сессий (П7, П8, П10)

Решение владельца **d-pipe-nerve = «да»** (28.10, заметка: «все сразу и сегодня, автозапуск и авто-действия делаем»).
Демон на Mac, только stdlib Python, под launchd. Будит сессию **только когда действовать нужно именно ей**,
вместо опросов, «как дела» и копий сообщений (правила 3–6 TEAM-0).

Состояние на 28.10 16:15 МСК: LaunchAgent `space.hrhelper.nerve` загружен, 15 тестов зелёные,
первый проход 59 с (засев GitHub), следующие ~6 с.

## Как устроено

```
источники (раз в 60 с; ночью ×5)          журнал state/journal.jsonl           тапы ролей (Monitor)
 GitHub: PR, головы, вердикты, CI  ─┐      append-only, ключ идемпотентности,   nerve.py tap <роль>
 очередь владельца: ответы, inbox  ─┼──►   запись ДО доставки           ──►     печатает строку, только
 транскрипты: расход $, отказы      │      класс: nervous | digest              когда роли действовать
 система: память, хаб :3050        ─┘      адресаты: роли / all
                    │
                    └─► авто-действия (actions.py) ─► state/mode.json (фаза, пауза, пачки, окно 5 ч)
```

- **nervous** — печатается сразу: ответ владельца на d-пункт, «стоп/откат» из inbox, кворум PR, лимит снят,
  предвестник лимита, критическая память, хаб лёг.
- **digest** — копится и выходит одной строкой раз в 30 мин (×2 в режиме пачек), только днём и не во время паузы:
  новый PR, changes автору, PR закрыт, approve автора не засчитан, обычный inbox, сбой и восстановление источника.
- **Кворум**: все ≥ 3 линзы одобрили одну голову, changes на ней нет, CI не в процессе → **один** раз будится
  Контроль (`release`), ключ `gh:quorum:<n>:<голова>`. Это замена сообщения «#n собран» (правило 3).
  Пустой список проверок — «в процессе»: CI ещё не стартовал (SE-126). Голова без единой проверки 30 мин — кворум
  с «CI: none» под ключом `gh:quorum:<n>:<голова>:none` и одно `pr.nochecks` координатору (дайджест). Появились
  проверки — кворум по ним обычным правилом. `STARTUP_FAILURE` — провал, `REQUESTED` — в процессе.
  Approve автора PR не считается (SE-121), если тело PR называет его строкой «роль N — автор»; базовая роль автора
  выпадает вместе со второй сессией. Пути файлов автора для кворума не дают: `boards/` — роль boards, а код
  `boards/apps/api` и `apps/web` пишут backend и frontend (из 169 открытых PR 15.11 по путям 17 потеряли бы
  кворум). Строка кворума называет не засчитанный approve, а если кворум ждёт только его — одно `pr.own` Контролю
  на голову (дайджест). Тело PR читается вместе с файлами: на новой голове и пока у головы нет проверок. Строку
  автора, дописанную позже без push, Нерв может не увидеть.
- **GitHub** (`gh_source.py`): все открытые PR одним `gh pr list --json number,headRefOid,updatedAt,createdAt,title`
  (до 1000) каждый проход: 46 КБ на 165 PR tAIBE против 3,45 МБ REST-страниц, чей etag менял каждый push (SE-119).
  PR, ждущий только CI, перепроверяется каждый проход: сначала статус проверок, комментарии — когда CI доехал.
  Голова без проверок дольше 30 мин — раз в 15 мин; комментарии при «CI: none» читаются один раз на голову.
  PR нет в списке → `gh pr view`: «влит» или «закрыт» только при `state ≠ OPEN`, ключ `gh:closed:<n>:<время>`.
  Первый проход новой ревизии состояния — догон: до 20 новых PR за проход, «открыт» — только у созданных после
  перехода. Граница перехода — самое позднее `updated` известных PR, а не старт процесса: PR, открытый в паузе
  перезапуска, получает «открыт» (SE-120). До 14.11 читалась одна страница из 50: старые открытые PR шли в дайджест
  как «закрыт».
- **Сторожа** (`guard_source.py`, TB-45 S45-4b; в проход пока не включён — ждёт ключ записи и маршрут S45-4a):
  завершённые прогоны CI ветки `board-agents` → исходящий ящик → `POST /api/forest/{ws}/guard-runs` (маршрут
  пространства, спека v0.8; карточки сопоставляет сервер). Один `gh api …/actions/runs?branch=…&created=>=<курсор>`
  раз в 5 мин; курсор — самый старый незавершённый прогон. Тот же запрос повторяется с `If-None-Match`, и без новых
  прогонов ответ — 304 без тела (замер 15.11: 604 КБ на первое чтение за 3 ч, 27 КБ на второе, 1,2 КБ на 304).
  Ответы досок: 400/413/422 и прочий 4xx (409…) — прогон отброшен, событие; 401/403/404 — событие на эпизод, ящик
  ждёт; 429 — повтор; 5xx, 408, сеть и неожиданный код дольше 2 чтений подряд — событие координатору на эпизод.
  Сбой gh не останавливает ящик: проход отправляет его и только потом пробрасывает исключение; следующее чтение —
  через 5 мин.
- **Маршрут ответа владельца**: по полю `source` пункта (`config.json → queue.source_roles`, регэкспы).
  Текст заметки владельца в журнал не пишется — только «есть заметка» (заметки бывают с PII и ссылками).

## Авто-действия (actions.py)

| Событие | Действие |
|---|---|
| Окно 5 ч израсходовано на 80 % от квоты окна | всем активным ролям: «допиши шаг, запиши work_state, тяжёлое не начинай» (не чаще раза в 5 ч) |
| Окно на 60 % | `mode.batch = true`: дайджест реже, линзы пачками |
| Отказ «hit your … limit» в транскрипте | Координатору одна строка; тапы молчат (`pause`) до сброса, кроме `limit.*` и `owner.stop` |
| Сброс прошёл **или** запросы снова проходят (сменили аккаунт) | активным ролям «лимит снят: продолжай с work_state»; придержанное печатается с пометкой |
| Сброс ночью (22:00–08:30) | будить в 08:30 |
| Недельный лимит | пункт владельцу `c-nerve-weekly-ГГГГММДД` (вид check), сначала GET — существующий не перезаписывается |
| Демон молчит дольше двух циклов (днём 5 мин, ночью 10: цикл 60 с × 5) | тапы `coord` и `release`: «НЕРВ МОЛЧИТ … launchctl kickstart -k …» (одна строка на эпизод) |

**Квота окна** — медиана расхода до отказа в последних 6 волнах (калибруется сама на каждой волне; на 28.10 — $17.2
по прайсу API). **Окно 5 ч** начинается не раньше последнего отказа или прошедшего сброса. **Неделя** — с четверга 19:00.
Расход — по прайсу API из `usage` транскриптов (как `tools/context_audit.py`): это мерило лимита, не деньги.
Пауза — по факту отказа, не по 502 (связь 502 с лимитом не доказана).

## Команды

```bash
N=eval/nerve
python3 -I $N/nerve.py status              # пульс, режим, лимит, волны, ошибки источников, последние адресные события
python3 -I $N/nerve.py tap <роль>          # ← Monitor роли, timeout_ms 3300000, по таймауту — перевзвод; --once — один проход
python3 -I $N/nerve.py tap <роль> --product taibe   # роль другого продукта (OPS-25); иначе TAIBE_PRODUCT, иначе по умолчанию
                                          # в журнал продукта: его PR; события аккаунта (budget.warn, limit.hit — coord,
                                          # limit.resume — живые роли); ответы на пункты с `-taibe-`; owner.stop (Ф2b)
python3 -I $N/nerve.py emit <роль> "текст" # назначение вручную (Координатор), класс nervous; роль — ключ, номер 1–8
                                          # (1 coord … 6 boards, 7 backend-2, 8 frontend-2, порядок team.roles), all или список через запятую;
                                          # неизвестное имя — код 2 и ничего не записано (иначе запись не слышит никто)
python3 -I $N/nerve.py once [--seed]       # один проход руками (демон держит замок — once его не берёт)
python3 -I -m unittest discover -s $N -p 'test_*.py'
```

Роли — `team.roles` в `config.json`, по порядку номеров реестра Т3: 1 `coord`, 2 `plan`, 3 `frontend`, 4 `backend`,
5 `release`, 6 `boards`, 7 `backend-2`, 8 `frontend-2`; ещё `supertick` и `tboards` (по `source` пунктов). `emit` и
`tap` принимают ключ или номер 1–8. Номер вне диапазона и неизвестное имя у `emit` дают код 2.
Вторая сессия роли (`backend-2`, `frontend-2`, решения владельца 14.11) — свой ключ и свой курсор: `emit backend` до
`backend-2` не доходит, `all` — доходит обеим. Геном и пусковой файл у неё — базовой роли (`products.base_role`,
`spawn_session.sh`), отдельного генома нет. Кворум считает её approve линзой базовой роли (`quorum.tally`, так же
`tools/release_status.py`), а changes — по точному ключу. `pr.changes` автору PR идёт базовой роли и её вторым
сессиям (`quorum.author_roles`): по путям файлов их не различить. Ответ владельца на пункт с `source`
«backend-2|Бэкенд-2|роль 7» (или frontend-2, роль 8) — второй сессии: эти правила `queue.source_roles` стоят до базовых.
Сессия роли ставит **один** Monitor: `python3 -I eval/nerve/nerve.py tap <роль>` — фильтр внутри, без `| grep`
(память `feedback_monitor_no_pipe_filters`). Курсор тапа — `state/tap-<роль>.json`, первый запуск начинает с конца журнала.
Пульс (`coord`, `release`) считается устаревшим через два цикла демона, но не раньше `heartbeat_stale_min`. Цикл
берётся из `state/cycle.json`: туда демон перед сном пишет фактическую паузу, включая ручной `run --interval N`.
Там же — счёт бодрствования системы (`awake`, `CLOCK_UPTIME_RAW` на macOS): `time.sleep` демона во сне Mac не идёт,
и ночная пауза растягивается на весь сон. Тишина — только когда порог прошли и стенные часы, и бодрствование с начала
этого сна (ночь 05.11: 88 мин по стене, 272 с бодрствования — четыре ложные тревоги в DarkWake). Нет `awake` (демон
старше правки), cycle прошлого прохода или счёт пошёл назад (перезагрузка) — только стенные часы, как раньше.

## Установка и откат

```bash
cp eval/nerve/space.hrhelper.nerve.plist ~/Library/LaunchAgents/   # из корня tAIBE
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/space.hrhelper.nerve.plist
launchctl kickstart -k gui/$(id -u)/space.hrhelper.nerve      # перезапуск после правки кода
launchctl bootout gui/$(id -u)/space.hrhelper.nerve           # ОТКАТ: сессии возвращаются к правилу 3 TEAM-0
```

Лог — `state/nerve.log` (в норме пуст: ошибки источников идут в журнал как `nerve.error`). Python —
`/Library/Frameworks/Python.framework/Versions/3.14/bin/python3`, не `/usr/bin/python3` (шим Xcode, лицензия не
принята). Перезапуск только при сбое (`KeepAlive.SuccessfulExit=false`), второй экземпляр выходит по замку.

## Границы

- Снаружи не меняется ничего, кроме пункта владельцу при недельном лимите (d4). PR, карточки, бот, прод — как были.
- Токен очереди — из связки ключей (`mcp-secret.sh OQ_TOKEN`), в curl идёт через stdin (`-H @-`), не в argv и не в лог.
- Python `urllib` на этой машине падает на SSL ops-консоли — поэтому curl.
- Смена аккаунта распознаётся эвристикой «после отказа снова есть расход > $0.05». Два аккаунта одновременно на разных
  сессиях она не различит (транскрипт аккаунт не пишет).
- `shadow/watchdog.py` (AUTH, STALE, DISK, APIERR) остаётся отдельным теневым наблюдателем; в Нерв перенесены
  LIMIT и MEM. Перенос AUTH — следующий шаг, если понадобится.
